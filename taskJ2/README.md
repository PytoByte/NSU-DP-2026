# taskJ2 — синхронизированный доступ к списку

Родительская нить кладёт строки из stdin в начало списка, N дочерних нитей
параллельно сортируют его «бесконечным пузырьком». Две реализации: `linked`
(свой односвязный список с поузловыми `ReentrantLock`) и `array`
(`Collections.synchronizedList(new ArrayList<>())`).

## Запуск

Нужны JDK 17+ и Gradle-wrapper (`./gradlew`).

```powershell
# интерактивно
./gradlew run --args="--type=linked --threads=3 --between=1000"
./gradlew run --args="--type=array  --threads=3 --between=1000"

# без Gradle (после ./gradlew classes)
java -cp build/classes/java/main org.example.app.Main --type=linked --threads=3 --between=1000

# замер: 50 записей, нити останавливаются после полной сортировки
java -cp build/classes/java/main org.example.app.Main --type=linked --threads=3 --benchmark=50
```

| аргумент | смысл | по умолчанию |
|---|---|---|
| `--type=linked\|array` | реализация списка | `linked` |
| `--threads=N` | число дочерних нитей | `3` |
| `--between=MS` | задержка между шагами | `1000` |
| `--inside=MS` | задержка внутри шага | `0` |
| `--max-line=N` (`--maxLine`) | порог резки строки | `80` |
| `--benchmark=N` | headless-замер на N записях | — |
| `--duration=MS` | ограничить замер окном в MS | — |

Пустая строка печатает текущий список; `Ctrl+D` / `Ctrl+Z` завершает работу и
печатает суммарное число шагов (`Sort steps count: N`).

## Теоретический расчёт

`n` — число записей, `k` — число нитей. Шаг — одно сравнение пары соседей.

1. Один поток. За проход `n-1` сравнений, проходов до полного порядка
   `P ≤ n-1`:

   `steps(1) = P·(n-1) ≤ (n-1)²`.

2. `k` потоков. Нити выполняют одни и те же проходы, то есть дублируют
   работу, поэтому суммарное число шагов растёт с `k` слабо:

   `steps(k) ≈ P·(n-1) + O(повторы при конкуренции)`.

## Статистика

`--benchmark=50`, `n = 50`, медианы 3 прогонов.

| нитей | `linked`, шагов | `array`, шагов |
|---:|---:|---:|
| 1 | 2254 | 2254 |
| 2 | 2303 | 2303 |
| 3 | 2352 | 2450 |
| 4 | 2401 | 2450 |

`2254 = 46·49 = P·(n-1)` — один поток, обе реализации (алгоритм один и тот же).
С ростом `k` суммарные шаги растут слабо: нити дублируют одни и те же проходы,
а лишние шаги — это повторные проверки и пропущенные пары при конкуренции.
